DESCRIPCION GENERAL DEL PROYECTO

Rueda Libre es un proyecto web para un negocio de alquiler
de bicicletas ubicado en Medellín, Colombia.

El sitio permite a los visitantes conocer el negocio,
consultar sus servicios, revisar las tarifas de alquiler
y los precios de los recorridos guiados, conocer los horarios
de atención y contactar al negocio para realizar reservas.

El proyecto se desarrolla con HTML y utiliza Git y GitHub
para controlar las versiones y guardar el historial
de los cambios realizados durante los MiniRetos.

OBJETIVO GENERAL

Construir un sitio web organizado, accesible y navegable,
utilizando HTML semántico, enlaces entre páginas, imágenes,
listas, tablas y una estructura de archivos clara.

2. ANALISIS DE LA PETICION DEL CLIENTE
------------------------------------------------------------

El cliente necesita un sitio web que permita a los usuarios
conocer Rueda Libre sin tener que solicitar toda la
información por WhatsApp.

La página debe presentar de forma clara:

- La identidad y presentación del negocio.
- El alquiler de bicicletas urbanas, de montaña y eléctricas.
- Los recorridos guiados disponibles.
- El servicio de taller básico.
- Los beneficios del alquiler.
- Los pasos para alquilar.
- Las tarifas y los precios por duración.
- Los horarios de atención.
- Los datos de contacto y las opciones de reserva.

La solución consiste en dividir el contenido en tres páginas
relacionadas mediante un menú de navegación común:

1. Inicio.
2. Tarifas y rutas.
3. Reservas.

La organización del contenido permite que el visitante
encuentre la información de forma más rápida y facilita
el mantenimiento futuro del sitio.

3. FUNDAMENTOS DE HTML
------------------------------------------------------------

HTML:
Es el lenguaje de marcado utilizado para definir la
estructura y el significado del contenido de una página web.

ESTRUCTURA BASE:

<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">
    <title>Titulo de la pagina</title>
</head>
<body>
    <!-- Contenido visible -->
</body>
</html>

DOCTYPE:
Indica que el documento utiliza HTML moderno.

html lang="es":
Indica que el idioma principal del contenido es español.

meta charset="UTF-8":
Permite representar correctamente caracteres especiales,
acentos y la letra ñ.

meta viewport:
Ayuda a que la página se adapte al ancho de la pantalla
del dispositivo.

title:
Define el título que aparece en la pestaña del navegador.

meta description:
Proporciona una descripción de la página que los motores
de búsqueda pueden utilizar como resumen.

------------------------------------------------------------
4. JERARQUIA DE ENCABEZADOS
------------------------------------------------------------

h1:
Es el encabezado principal de la página. En este proyecto
se utiliza un solo h1 por documento.

h2:
Representa las secciones principales, por ejemplo:
¿Quiénes somos?, Nuestros servicios y ¿Cómo alquilar?

h3:
Representa subsecciones, como los servicios individuales
dentro de Nuestros servicios.

La jerarquía se define según la relación entre los temas
y no únicamente según el tamaño visual de las letras.

Los encabezados permiten comprender la organización del
contenido y facilitan la navegación con tecnologías
de asistencia.

------------------------------------------------------------
5. ELEMENTOS DE TEXTO Y LISTAS
------------------------------------------------------------

p:
Define un párrafo.

strong:
Marca texto de especial importancia. Por ejemplo:
"El alquiler incluye casco y candado".

em:
Añade énfasis a una expresión.

ul:
Crea una lista no ordenada, normalmente presentada
con viñetas. Se utiliza para presentar los beneficios
y los elementos que deben llevar los usuarios.

ol:
Crea una lista ordenada, normalmente numerada.
Se utiliza para presentar los cuatro pasos del alquiler.

li:
Representa cada elemento de una lista.

dl:
Crea una lista de descripciones o definiciones.

dt:
Identifica el término o elemento descrito, como
"Lunes a viernes".

dd:
Contiene la descripción correspondiente, como el horario
"7:00 a. m. a 7:00 p. m.".

------------------------------------------------------------
6. IMAGENES Y RUTAS RELATIVAS
------------------------------------------------------------

Las imágenes se incorporan mediante la etiqueta img.

Ejemplo desde index.html:

<img src="img/bicicleta.jpg"
     alt="Bicicleta disponible para alquilar"
     width="500">

src:
Indica la ubicación del archivo de imagen.

alt:
Proporciona una descripción textual de la imagen.

width:
Define el ancho de la imagen en píxeles.

Las rutas utilizadas son relativas al archivo HTML
desde el cual se solicita el recurso.

Desde index.html hacia una imagen:

img/bicicleta.jpg

Desde paginas/tarifas.html hacia el logo:

../img/logo.png

El segmento ../ permite subir un nivel desde la carpeta
paginas hasta la carpeta principal.

No se deben utilizar rutas locales de Windows, como
C:\Users\..., porque no funcionan como rutas del sitio
cuando se publica en otro computador o servidor.

7. ENLACES Y NAVEGACION
------------------------------------------------------------

Los enlaces se crean con la etiqueta a y el atributo href.

ENLACE ENTRE CARPETAS:

<a href="paginas/tarifas.html">Tarifas y rutas</a>

Desde index.html hacia reservas:

Desde tarifas.html hacia Inicio:

Desde tarifas.html hacia reservas:

ENLACE A UNA SECCION DE OTRA PAGINA:

<a href="paginas/tarifas.html#recorridos">
    Consultar recorridos guiados
</a>

El fragmento #recorridos lleva a la sección que tenga
el atributo id="recorridos".

ENLACE DE CORREO:

<a href="mailto:hola@ruedalibre.example">
    Escríbenos
</a>

El prefijo mailto: solicita abrir la aplicación de correo
configurada en el dispositivo.

ENLACE EXTERNO EN OTRA PESTAÑA:

<a href="https://www.google.com/maps/search/?api=1&amp;query=Medellin%2C+Colombia"
   target="_blank"
   rel="noopener noreferrer">
    Ver ubicación en Google Maps
</a>

target="_blank":
Solicita abrir el destino en otra pestaña.

rel="noopener noreferrer":
Añade protección al abrir un enlace en otra pestaña.

NOTA:
La búsqueda de Google Maps utilizada es una ubicación
general de Medellín y no una dirección comercial verificada
de Rueda Libre.

El correo hola@ruedalibre.example es una dirección
de ejemplo y no se ha verificado que exista.

10. ESTRUCTURA SEMANTICA DEL DIA 2
------------------------------------------------------------

El HTML semántico permite identificar la función de las
distintas regiones del documento.

header:
Contiene información introductoria o encabezados.
En este proyecto se utiliza para el encabezado del sitio.

nav:
Identifica el menú principal de navegación.

main:
Contiene el contenido principal de la página.
Cada documento debe tener un único main visible.

section:
Agrupa contenido relacionado por tema y debe tener
un encabezado apropiado.

article:
Representa una unidad de contenido independiente.
En Inicio se utiliza para cada servicio:
- Alquiler de bicicletas.
- Recorridos guiados.
- Taller básico.

aside:
Representa contenido complementario.
En Tarifas se utiliza para la información adicional
y la lista de qué llevar.
En Reservas se utiliza para el horario de atención.

footer:
Representa el pie de página. Contiene el nombre del negocio,
el correo de contacto y el año.

div y span:
Son elementos genéricos que pueden utilizarse cuando no
existe un elemento semántico más apropiado.

En la versión reconstruida de las tres páginas no se
necesitaron div ni span. Si se incorporan posteriormente
para organizar estilos, se debe justificar su uso.

13. ANALISIS DE LA PETICION AL SERVIDOR
------------------------------------------------------------

Cuando una persona abre una página web, el navegador realiza
una petición HTTP al servidor para solicitar el documento
HTML o los recursos que necesita.

Ejemplo del flujo de carga:

1. El usuario abre index.html mediante el navegador
   o mediante un servidor de desarrollo como Live Server.

2. El navegador solicita el documento HTML.

3. El servidor devuelve el documento solicitado.

4. El navegador interpreta el HTML y construye el árbol
   de elementos del documento.

5. El navegador solicita recursos adicionales, como
   imágenes, hojas de estilo y archivos JavaScript,
   cuando están referenciados.

6. El navegador presenta el contenido al usuario.

7. Cuando el usuario pulsa un enlace a tarifas o reservas,
   el navegador solicita el documento de destino.

8. Si la ruta es incorrecta, el recurso puede no encontrarse
   y aparecer un error 404.

En DevTools, la pestaña Network permite revisar las peticiones,
los recursos solicitados y los códigos de estado.

Un código 200 suele indicar que la petición se completó
correctamente. Un código 404 indica que el recurso solicitado
no se encontró en esa ruta.

La disponibilidad de un archivo depende de la estructura
real del proyecto y de cómo se sirve o publica el sitio.

## Reto: Formulario de reserva en HTML

### Objetivo

Construir un formulario de reserva para Rueda Libre que permita recopilar los datos del cliente y las características del alquiler de bicicletas. El formulario busca reducir errores en la información recibida por WhatsApp y organizar los datos necesarios para solicitar una reserva.

### Archivo modificado

- `paginas/reservas.html`

### Estructura semántica

Se mantuvo la estructura semántica implementada en el reto anterior:

- `<header>`: contiene el título de la página y la navegación principal.
- `<nav>`: permite acceder a Inicio, Tarifas y Reservas.
- `<main>`: contiene el contenido principal de la página.
- `<section>`: agrupa el formulario y la información de contacto.
- `<form>`: contiene los campos que debe completar el cliente.
- `<fieldset>`: agrupa campos relacionados.
- `<legend>`: identifica cada grupo del formulario.
- `<aside>`: contiene información complementaria sobre los horarios.
- `<footer>`: presenta la información final del sitio.

### Organización del formulario

El formulario se dividió en tres grupos:

**1. Tus datos**

- Nombre completo.
- Número de documento.
- Correo electrónico.
- Celular.

**2. Tu alquiler**

- Fecha del alquiler.
- Tipo de bicicleta: urbana, montaña o eléctrica.
- Plan: una hora, medio día o día completo.
- Cantidad de bicicletas.
- Recorrido guiado: ninguno, Río y Parques, Sabores de Barrio o Reto Las Palmas.
- Comentarios adicionales.

**3. Confirmación**

- Casilla para aceptar las políticas de alquiler.

Al final se agregó el botón «Enviar reserva».

### Tipos de controles utilizados

- `text`: para el nombre completo y el número de documento.
- `email`: para el correo electrónico.
- `tel`: para el número de celular.
- `date`: para seleccionar la fecha del alquiler.
- `radio`: para elegir un único tipo de bicicleta.
- `select` y `option`: para seleccionar el plan y el recorrido guiado.
- `number`: para indicar la cantidad de bicicletas.
- `textarea`: para escribir comentarios adicionales.
- `checkbox`: para aceptar las políticas de alquiler.
- `button type="submit"`: para enviar el formulario.

### Justificación de tres decisiones

**1. Correo electrónico con `type="email"`**

Se eligió este tipo de campo porque permite al navegador comprobar que el valor ingresado tenga un formato similar al de una dirección de correo electrónico. Esto ayuda a detectar errores comunes antes de enviar el formulario.

**2. Tipo de bicicleta con botones `radio`**

Se utilizaron botones de opción porque el cliente debe escoger solamente una categoría de bicicleta para la reserva. Los tres controles comparten el atributo `name="tipo_bicicleta"`, por lo que el navegador permite seleccionar solo una opción de ese grupo.

**3. Aceptación de políticas con `checkbox`**

Se eligió una casilla de verificación porque representa una aceptación que el cliente debe marcar expresamente. El atributo `required` impide el envío normal del formulario si la casilla no está seleccionada.

**Decisiones adicionales**

- Se usó `type="date"` para facilitar la selección de una fecha.
- Se usó `type="number"` para la cantidad de bicicletas y se establecieron límites de 1 a 20.
- Se usaron listas desplegables para el plan y el recorrido, ya que tienen opciones definidas.
- Se utilizó `textarea` para permitir comentarios de varias líneas.

### Asociación entre etiquetas y controles

Cada campo tiene una etiqueta `<label>` con el atributo `for`. El valor de `for` coincide exactamente con el `id` del control correspondiente. De esta manera, al hacer clic en la etiqueta, el control recibe el foco o se selecciona, según el tipo de campo.

Todos los controles del formulario tienen un atributo `name`, que identifica el dato al enviar el formulario.

### Método y validaciones

El formulario utiliza:

- `method="post"` para indicar que los datos se enviarían mediante el método HTTP POST.
- `action="#"` como destino provisional mientras no se implemente un servidor que reciba las reservas.
- `required` en los campos obligatorios.

### Objetivo

### Validaciones implementadas

Se añadieron atributos HTML para comprobar los datos antes de permitir el envío normal del formulario:

**Documento**

El patrón `[0-9]{6,10}` permite únicamente dígitos del 0 al 9, con una longitud de entre 6 y 10 caracteres. El atributo `title` explica que no deben incluirse puntos, espacios ni guiones.

**Celular**

El patrón `3[0-9]{9}` exige que el primer dígito sea 3 y que después existan exactamente nueve dígitos adicionales. Por ejemplo, `3001234567` debe aceptarse, mientras que `1234567890` y `300123` deben rechazarse.

En CSS, la especificidad se calcula de forma simplificada con tres grupos:
(A, B, C)

A = cantidad de selectores de ID.
B = cantidad de clases, atributos y pseudoclases.
C = cantidad de selectores de elemento y pseudoelementos.

Selector: #menu a
Especificidad: (1, 0, 1)
Explicación: contiene un ID (#menu) y un elemento (a).

Selector: .activo
Especificidad: (0, 1, 0)
Explicación: contiene una clase.

Selector: #menu a.activo
Especificidad: (1, 1, 1)
Explicación: contiene un ID, una clase y un elemento.

Selector: #menu a:hover
Especificidad: (1, 1, 1)
Explicación: contiene un ID, una pseudoclase y un elemento.

Selector: #menu a.activo:hover
Especificidad: (1, 2, 1)
Explicación: contiene un ID, dos pseudoclases/clases y un elemento.

Selector: .boton-accion
Especificidad: (0, 1, 0)
Explicación: contiene una clase.

    font-weight: 600;
}

La clase .activo no puede imponerse por sí sola a #menu a cuando ambas reglas declaran la misma propiedad, porque el selector con ID tiene mayor especificidad.

Comparación:
- #menu a = (1, 0, 1).
- .activo = (0, 1, 0).

El selector #menu a gana por tener un ID, aunque .activo aparezca después en el archivo CSS.

Solución aplicada:
Se utiliza un selector más específico para la página actual:

#menu a.activo {
    color: var(--naranja-pedal);
    font-weight: 700;
}

Su especificidad es (1, 1, 1), por lo que supera a #menu a, cuya especificidad es (1, 0, 1).

La solución no utiliza !important ni estilos en línea. Los colores del enlace activo respetan el mapa de marca: Naranja Pedal sobre Azul Noche.

5. NAVEGACIÓN Y PSEUDOCLASES

Se utiliza #menu a para seleccionar enlaces descendientes de la lista del menú.

Estados definidos:
- #menu a:hover: cambia el fondo a Verde Ruta y conserva el texto Crema.
- #menu a:focus: dibuja un contorno Crema visible al navegar por teclado.
- #menu a.activo: distingue la página actual con Naranja Pedal sobre Azul Noche.
- #menu a.activo:hover: mantiene la apariencia del enlace activo y evita perder su identificación.

Los enlaces del contenido también cuentan con :hover y :focus.

2. BOX MODEL

El modelo de caja está compuesto por:

- Content: área donde aparece el contenido.
- Padding: espacio interno entre el contenido y el borde.
- Border: borde que rodea el elemento.
- Margin: espacio externo que separa un elemento de los demás.

Se agregó esta regla global:

*,
*::before,
*::after {
    box-sizing: border-box;
}

Con border-box, el ancho declarado incluye el contenido, el padding y el borde. Esto facilita calcular dimensiones y evita que el relleno haga que una tarjeta supere el ancho previsto.

3. CONTENEDOR PRINCIPAL

El elemento main utiliza:
- width: 92%.
- max-width: 70rem.
- margin-left: auto.
- margin-right: auto.

El ancho porcentual permite adaptarse a pantallas pequeñas, mientras que max-width limita el ancho en pantallas grandes. Los márgenes automáticos centran el contenido.

La portada principal utiliza la clase .portada y min-height: 60vh. Esto establece una altura mínima equivalente al 60 % de la altura de la ventana del navegador.

4. TARJETAS DE SERVICIOS

La sección #servicios utiliza CSS Grid para distribuir las tarjetas.

Las reglas principales son:
- Tres columnas en pantallas amplias.
- Dos columnas en pantallas medianas.
- Una columna en pantallas pequeñas.
- Separación entre tarjetas mediante var(--espacio-grande).
- Relleno interno mediante var(--espacio-mediano).
- Borde de 1px.
- Esquinas redondeadas mediante var(--radio-borde).
- Imágenes con width: 100% y max-width: 100%.

Se utiliza min-width: 0 en las tarjetas para permitir que se ajusten a las columnas sin desbordarse.

5. TABLAS

Las tablas de tarifas y recorridos se mejoraron mediante:
- width: 100%.
- padding en las celdas.
- Bordes de 1px.
- Encabezados con fondo Azul Noche y texto Crema.
- Alineación vertical superior.
- Separación inferior con la escala de espaciado.
- Desplazamiento horizontal en pantallas estrechas.

El contraste de los encabezados utiliza la combinación aprobada de texto Crema sobre Azul Noche.

6. FORMULARIO

7. NAVEGACIÓN

La lista #menu utiliza:

- flex-direction: row.
- flex-wrap: wrap.
- gap: var(--espacio-mediano).

Esto presenta las opciones en una fila cuando existe espacio suficiente y permite que pasen a otra línea si la pantalla es estrecha.

Los enlaces mantienen la clase activo para identificar la página actual.

8. UNIDADES CSS UTILIZADAS

rem:
- Escala de espaciado.
- Ancho máximo del contenido.
- Ancho máximo del formulario.
- Rellenos, márgenes y radios.
- Indicadores de foco.

%:
- Ancho del contenedor principal.
- Ancho de las imágenes de las tarjetas.
- Ancho de los campos del formulario.

vh:
- Altura mínima de la portada.

px:
- Bordes de tarjetas, tablas, campos y botones.

La escala de espaciado es:
- 0.5rem: espacio pequeño.
- 1rem: espacio mediano.
- 2rem: espacio grande.
- 3rem: espacio extra grande.

### 1. Actividades realizadas

- Se integró Bootstrap 5.3.3 mediante CDN en las páginas Tarifas y Reservas.
- Se utilizaron los contenedores `container` para organizar el contenido.
- Se implementaron las clases `row` y `col-*` para distribuir los elementos de las páginas.
- Se adaptó la estructura del formulario de reservas utilizando componentes y clases de Bootstrap.

- Se conservaron los estilos de las tarjetas, tablas, botones, encabezados, pie de página y acceso fijo a WhatsApp.

### 2. Uso de Bootstrap

Se utilizaron principalmente las siguientes clases:

- `container`: organiza y limita el ancho del contenido.
- `row`: crea filas para organizar los elementos.
- `col-12`: permite ocupar todo el ancho disponible.
- `col-md-*`: establece distribuciones diferentes en pantallas medianas.
- `col-lg-*`: permite adaptar la distribución a pantallas grandes.
- `g-4`: establece espacios entre columnas y filas.
- `form-control`: aplica estilos de Bootstrap a los campos de entrada.
- `form-select`: adapta las listas desplegables.
- `form-check`: organiza las casillas de verificación.

### 3. Actualización del CSS

Se reorganizó `css/styles.css` para mantener únicamente los estilos personalizados necesarios para la identidad visual y presentación del proyecto.

Se conservaron:

- Variables de colores corporativos.
- Tipografías Montserrat y Open Sans.
- Estilos del encabezado y logo.
- Apariencia del menú de navegación.
- Estilos de portada y tarjetas.
- Presentación de precios y tablas.
- Apariencia de los formularios.
- Estilos del pie de página.
- Botón fijo de WhatsApp.

Se retiraron reglas de distribución que duplicaban las funcionalidades de Bootstrap, como las relacionadas con CSS Grid y Flexbox en la estructura de reservas.

### 4. Pruebas y validación

Se estableció como criterio de revisión comprobar el comportamiento responsive del sitio en tres resoluciones:

- 360 px: dispositivos móviles.
- 768 px: tabletas y pantallas medianas.
- 1280 px: computadores de escritorio.

Las páginas que deben validarse son:

- Inicio.
- Tarifas y rutas.
- Reservas.

Se debe verificar que las tablas no provoquen desbordamientos, que el formulario conserve sus validaciones y que los elementos mantengan una presentación adecuada en diferentes tamaños de pantalla.

### 5. Comparación entre CSS personalizado y Bootstrap

La migración permite utilizar un sistema de diseño responsive ya establecido, reduciendo la necesidad de escribir reglas propias para columnas, filas y distribución de elementos.

La identidad visual continúa dependiendo del CSS personalizado, mientras que Bootstrap se encarga principalmente de la estructura y adaptación responsive.

La migración de las páginas Tarifas y Reservas permite avanzar hacia una estructura más organizada y responsive mediante Bootstrap 5.3.3.

# RETO 10 – Navegación, pseudoclases y accesibilidad
Semana: 2  Día: 3  
============================================================

### Objetivo
Mejorar la experiencia de navegación del sitio web mediante selectores CSS, clases, identificadores, pseudoclases y el control de la especificidad. También se buscó garantizar que los elementos interactivos fueran visibles y accesibles al utilizar el teclado.

### Actividades realizadas

1. **Identificación de la página activa:** se utilizó el identificador `id="menu"` en la navegación y la clase `activo` junto con `aria-current="page"` en el enlace correspondiente a cada página.

2. **Especificidad y cascada CSS:** se revisó el conflicto entre los selectores `#menu a` y `.activo`. Se identificó que `#menu a` tiene una especificidad de 101, mientras que `.activo` tiene una especificidad de 10. Para resolver el conflicto se utilizaron selectores más específicos, sin recurrir a `!important` ni a estilos en línea.

3. **Estilos de navegación:** se utilizaron selectores descendientes para personalizar los enlaces del menú y se definieron estados visuales mediante las pseudoclases `:hover` y `:focus`.

4. **Botones de acción:** se reutilizó la clase `boton-accion` para dar apariencia de botón a los enlaces de reserva. Se agregaron estados para el paso del mouse y el enfoque mediante teclado.

5. **Campos de formulario:** se personalizaron los estados `:hover` y `:focus` de los campos de texto, listas desplegables y casillas de verificación.

6. **Accesibilidad:** se incorporaron indicadores visuales de enfoque para facilitar la navegación mediante la tecla Tab, evitando que el usuario pierda de vista el elemento seleccionado.

7. **Pruebas:** se revisaron las tres páginas del sitio —Inicio, Tarifas y rutas, y Reservas— y se utilizaron las herramientas de desarrollador para inspeccionar los estilos y comprobar los estados interactivos.

### Conceptos aprendidos

- Selectores por identificador (`#`).
- Selectores por clase (`.`).
- Selectores descendientes.
- Pseudoclases `:hover` y `:focus`.
- Cascada y especificidad CSS.
- Inspección de reglas CSS desde DevTools.
- Accesibilidad mediante navegación por teclado.
- Indicadores visuales de enfoque.

### Resultado

Se mejoró la navegación de Rueda Libre, diferenciando visualmente la página activa y proporcionando respuestas visuales al pasar el mouse o utilizar el teclado.
También se resolvieron conflictos de especificidad sin utilizar `!important`, manteniendo los estilos organizados y reutilizables.

# RETO 11 – Modelo de caja y espaciado con CSS

============================================================

**Objetivo:** Mejorar la distribución visual de Rueda Libre mediante el uso del modelo de caja, unidades relativas y propiedades de espaciado en CSS.

### 1. Modelo de caja
Se verificó la propiedad `box-sizing: border-box` para que el ancho y alto de los elementos incluyan el contenido, el padding y los bordes. También se revisó la importancia de esta propiedad para controlar mejor las dimensiones de los componentes.

### 2. Ancho y centrado del contenido
Se creó la clase `.contenido-principal`, utilizando `max-width` con unidades `rem` y márgenes automáticos para limitar el ancho del contenido y mantenerlo centrado en las páginas.

### 3. Sección principal
Se ajustó la sección de portada mediante `min-height` con unidades `vh`, permitiendo establecer una altura mínima proporcional al tamaño de la ventana del navegador.

### 4. Tarjetas y espaciado
Se revisaron los estilos de las tarjetas de servicios, rutas y bicicletas. Se utilizaron propiedades como `padding`, `border`, `border-radius` y `gap` para mejorar la separación y presentación de los elementos. Las imágenes se mantienen adaptables al ancho de sus contenedores.

### 5. Tablas
Se mejoró la presentación de las tablas de tarifas y recorridos mediante el uso de bordes, relleno interno en las celdas y colores de fondo para los encabezados, manteniendo el contraste con los colores corporativos.

### 6. Formularios
Se ajustaron las etiquetas para que aparezcan encima de los campos, se estableció el ancho completo para los controles y se mejoró la separación entre grupos de información y el espacio interno de los botones.

### 7. Menú de navegación
Se utilizó Flexbox mediante `display: flex` y `flex-wrap: nowrap` para organizar las opciones del menú en una sola fila.

### 8. Herramientas de desarrollo
Se utilizó la herramienta DevTools del navegador, en la pestaña Computed, para revisar las dimensiones de los elementos y comparar el comportamiento del modelo de caja antes y después de aplicar `box-sizing: border-box`.

### Resultado
Se mejoró la distribución del contenido, la legibilidad de las tablas, el espaciado de los formularios y la presentación de las tarjetas. El sitio mantiene su identidad visual y una estructura adaptable a diferentes tamaños de pantalla.
